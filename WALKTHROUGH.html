System Architecture

Microservices Topology & Data Boundaries

Gemini Bank implements strict domain isolation following the Database-per-Service pattern. Each microservice is independently deployable and guards its own persistent storage or in-memory projections.

Java Spring Boot / Python Dev

The core transactional book of records. Enforces atomic double-entry bookkeeping, positive amount validations, sufficient balance checks, and stores every transaction immutable in integer cents.

Transaction Execution & Security Propagation Flow

How an internal payment from Ana to Bruno is verified, tokenized, and committed across service boundaries:

1
User Authentication & Session: Browser posts credentials to Frontend (:8080). Frontend relays to Users (:8081), which mints a signed JWT with claims {sub, username, is_staff, exp}. Frontend persists this in an HTTP-only session cookie.
2
Identity Header Propagation: On every privileged action, Frontend validates the JWT and injects downstream headers: X-User-Id, X-Username, and X-Is-Staff.
3
Integer Conversion & Ledger Settlement: Frontend converts €75.50 to 7550 cents and calls POST http://ledger:8082/payments/internal. The Ledger verifies Ana's balance in an atomic transaction, writes a payment_out debit row (-7550) for Ana, writes a payment_in credit row (+7550) for Bruno, and commits ACID.
4
CQRS Cache Invalidation: Frontend notifies Statements (:8083) to refresh or invalidate its in-memory monthly aggregates, ensuring instant reporting synchronization.

Financial Architecture

The Ledger Invariant Engine: Precision & ACID Guarantees

In financial software, precision is non-negotiable. Floating-point arithmetic (e.g. standard IEEE 754 floats or doubles) introduces silent rounding drift that violates audit compliance. Gemini Bank solves this at the database schema level.

Architecture Layer Gemini Bank Implementation Financial Safety Benefit
Currency Representation INTEGER CENTS (e.g., €10.50 = 1050) Eliminates binary floating-point representation errors and fractional cent discrepancies.
Transfer Atomicity Two-legged single transaction block (@Transactional) Prevents orphaned debits or credits. Either both accounts update or neither does.
Amount Validation Strict assertion: amount_cents > 0 Prevents malicious negative payment attacks (which would invert debit into a credit).
Overdraft Protection Pre-execution check: current_balance >= amount Rejects transfers exceeding available balance before touching persistent state.
Identity Security Symmetric HMAC-SHA256 JWT + Header Propagation Ensures callers can only access and transfer funds from accounts they legally own.
Risk & Fraud Analytics

Authorized Push Payment (APP) Fraud Scenarios

Unlike unauthorized fraud (where a hacker steals credentials), APP scams trick legitimate users into authorizing transfers themselves. The synthetic dataset in seed.py introduces 3 realistic scam vectors directly into Ana Ferreira's account for testing fraud detection models.

Product Backlog & Vision

Strategic Product Roadmap: From MVP to Enterprise

Structured backlog prioritization prepared for the Product Owner, dividing engineering focus between immediate functional hardening, risk controls, and cloud scalability.

Phase 1 · Immediate MVP

UX & Functional Hardening

Target: Next Sprint (Weeks 1-2)
  • In-App Account Creation: Allow authenticated users to open secondary savings or checking accounts via UI.
  • Two-Step Payment Confirmation: Modal summary showing beneficiary details and balance impact before committing.
  • Privacy-Preserving Payee Lookup: Replace exposed internal accounts dropdown with an IBAN or handle search.
  • Statement PDF / CSV Export: Enable downloadable statements for customer tax and accounting compliance.
Phase 2 · Risk & Intelligence

AI Fraud Defense & Security

Target: Quarter 1
  • Confirmation of Payee (CoP): Name-matching verification before executing external transfers.
  • Real-time APP Scam Detection: ML NLP scoring on payment description field (flagging urgency phrases like "URGENT", "crypto", "release fee").
  • Asymmetric Token Architecture: Transition from shared HS256 secret to RS256/ECDSA public-private keys.
  • Push Notifications: Instant alerts on outgoing and incoming payments via WebSockets.
Phase 3 · Enterprise Scale

Cloud Native Architecture

Target: Quarter 2
  • Database Modernization: Migrate from SQLite to Cloud Spanner or Cloud SQL PostgreSQL for distributed HA.
  • Event-Driven CQRS: Decouple Ledger and Statements via Apache Kafka / Google Cloud Pub/Sub.
  • Multi-Currency Engine: Support foreign exchange (FX) conversion rates with live spot pricing.
  • Audit & Regulatory Vault: Immutable WORM (Write Once, Read Many) logging for banking compliance.
